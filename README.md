# Fractured Wavetable

**A browser-native tool for sound designers, sound explorers, and synthesizer programmers.**

Live project: <https://atom-smasher.github.io/Fractured-Wavetable-Generator/>

Fractured Wavetable Generator (FWG) creates oscillator waves, wavetables, START→END morphs, drones, pads, hits, transitions, growls, clangs, texture beds, sampler sources, modulation contours, and raw material for resynthesis.

The current release is **v3.1**. The previous stable release is v3.0.1.

Start with the volume low. FWG can deliberately produce abrupt, bright, aliased, folded, clipped, unstable, or full-scale digital material.

## Outputs are yours

Audio, WAV, and JSON files generated by FWG are user-created outputs. The program's GPL notice applies to the program itself; it does not, by itself, impose GPL licensing on generated outputs.

## Workspaces

FWG has six main workspaces:

- **Single Engine / Playground** — design and audition one endpoint.
- **START→END Morph** — design two endpoints and define their relationship.
- **Bulk Random** — broad seeded discovery from curated pools.
- **Bulk Explorer** — repeatable local or broad variation around an explicit source design.
- **Calculators** — plan pitch, sample counts, duration, wavetable geometry, and multisamples.
- **Notes** — compact in-app reference for shortcuts, limits, and advanced behaviour.

## Noise and Evolving generators

**Noise Smooth** is a frozen deterministic coloured-noise wavetable. **Noise Crunchy** advances a hidden deterministic stochastic epoch once per Root cycle; visible Stochastic Index offsets the same state axis.

The three **Evolving** families change independently of oscillator pitch. Evolution Rate is calibrated as an effective broad-timbre rate rather than a claim that every internal process runs at one literal oscillator frequency.

Temporal generators separate:

1. temporal/state ownership;
2. requested table-update cadence;
3. Root-cycle-safe completed-table adoption; and
4. a history-safe completed-table replacement transition.

This lets temporal sound design remain deterministic while avoiding arbitrary mid-cycle table swaps.

## Drawn: waveform construction and transforms

Drawn is each patch's editable 512-internal-cycle-sample waveform and can also be used as a Scanning LFO contour.

A current schema-14 numeric Drawn recipe reads naturally as a pipeline:

```json
{
  "data": [0, 1, -1],
  "resample_mode": "cardinal=0.79",
  "wrap": true,
  "transform": "walsh=15:",
  "normalise": true
}
```

`data`, `resample_mode`, and stage-1 `wrap` first construct the ordinary bounded 512-internal-cycle-sample Float32 Drawn waveform. Optional `transform` then receives exactly that materialised waveform. Optional `normalise:true` applies one final uniform gain around zero while preserving DC and waveform proportions.

Current construction families include linear, parameterised Steps, signed Power / symmetric Power, superellipse, Cardinal / Cardinal Limit / Cardinal Clip, and Fourier/Fourier-clip. Fourier remains useful as a direct sparse construction mode because an arbitrary N-point DFT has a clear meaning.

The v3 whole-waveform transform collection is:

- **Fourier / Fourier-clip** — global sinusoidal harmonic components;
- **Haar / Haar-clip** — local dyadic mean/detail bands;
- **Walsh / Walsh-clip** — global rectangular Walsh-Hadamard components in sequency order.

Haar and Walsh are transform-only. They analyse an already completed 512-internal-cycle-sample Drawn waveform rather than hiding another sparse interpolation policy.

The shared selector grammar is compact:

```text
N       exact component N
-N      exact component N with coefficient polarity inverted
:B      0 through B
A:      A through the maximum
A:B     inclusive range
comma   union
```

Examples:

```text
fourier=:8,-3
haar=:5,-5
walsh=15:
walsh=:80,-37
```

Fourier exposes 257 unique real orders `0…256`; Haar exposes bands `0…9`; Walsh exposes sequency `0…511`.

Haar is alignment-sensitive: moving the same completed waveform across its fixed half/quarter/eighth/etc. boundaries can redistribute energy among Haar bands. A Fourier circular shift instead preserves harmonic magnitudes while rotating harmonic phase. FWG does not add hidden Haar phase correction.

For numeric `data:[...]`, an ordinary numeric-array `format` label does not decide current semantics and new numeric examples/exports omit it. Standard JSON number syntax remains standard JSON (`0.3`, not `.3`). For optional Drawn pipeline fields, omit `transform`/`normalise` when unused; `transform:null`, `transform:""`, and `normalise:null` are invalid explicit authoring values, while `wrap:null` retains the ordinary open/default topology.

## Signal path

Ordinary generator families include Clean Chaos, Classic Waveforms, Classic Split, Phase Lattice, Phase Distortion, FM, Pulse Warp, Sync, Formant, **Throat**, Fold, Bitcrush, Harmonic Cluster, Modal, Feedback Sine, **Noise**, and the three **Evolving** families (Spectrum, Phase Distortion, FM), each with Smooth and Crunchy directions where applicable.

Input 1 and Input 2 select source taps A–D or Drawn. Wavetable Type combines them. Source and Result Windows shape the internal cycle before and after that collision stage. Endpoint modulation/filtering and Morph processing follow downstream.

## Import, export, and reconstruction

FWG exports mono WAV at common 44.1/48 kHz-family sample rates through 192 kHz and 8-, 12-in-16-, 16-, 24-, or 32-bit integer PCM.

Current JSON exports use **schema 14** and deterministic `.json.gz` by default. Plain `.json` remains importable. Public v2.9c/schema-12 and v3.0/v3.0.1 schema-13 files remain explicitly supported through documented migration paths.

Schema 14 versions the **document language**, not a closed feature catalogue. Adding a generator, filter, modulator, Wavetable Type, Morph mode, or similar categorical feature does not by itself require a new schema number. Unknown or malformed reconstruction-affecting identities fail closed instead of silently becoming defaults. Schema 14 distinguishes omission from explicit `null`/blank/falsey values and requires documented JSON types rather than JavaScript coercion. It also uses the canonical current Explorer-recipe field spellings rather than preserving development-only aliases from pre-release v3.1 builds. `required_capabilities` handles future semantics added beneath otherwise familiar identities.

Drawn uses one active saved waveform authority at a time. A pristine construction pipeline may be retained in full sidecars. After editing/flattening, literal 512-internal-cycle-sample Float32 `data` becomes authoritative. Schema 14 may retain the originating `construction` beside that data as non-DSP provenance for manual recovery; valid explicit data wins, and malformed explicit data fails rather than falling back. Standalone Export Drawn therefore writes literal editable samples while preserving a known recipe only as provenance.

## Audition envelopes

Audition de-clicking is preview-only and does **not** modify exported PCM.

- live drones/transport use a **20 ms linear attack**;
- pre-rendered one-shot Morph audition uses a **20 ms rising-cosine attack**;
- both use a **50 ms falling raised-cosine release**.

The live transport release is owned by the Web Audio clock so restart/control writes do not collide with an in-flight `AudioParam` release curve.

## Deterministic randomisation

v3 uses SHA-256 named draws rather than one mutable sequential random stream. This allows addressed decisions to remain reproducible without unrelated branches shifting each other merely because a new draw was inserted elsewhere.

## Phase-Coherent Mode

Phase-Coherent Mode performs best-effort registration of completed wavetables using exact integer circular rotations of the 512-internal-cycle-sample table. It is optional and workspace-local. MPC setup enables it in the active workspace but does not permanently own its later state.

## Browser target

The primary qualified target is a current desktop Brave/Chromium-family browser. Web Audio is required for auditioning; Web MIDI remains browser/platform dependent.

FWG is delivered as one HTML/JavaScript application. No compilation or installation step is required. Release packages may distribute that HTML as deterministic `.html.gz`; decompress it before opening the local file in a browser.
